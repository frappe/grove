# `infrastructure/` — a box, and what it stands on

The machines Grove runs on, the servers standing on them, the networks and geographies they sit in,
and the code that builds, names and changes one. What a box is *pushed* is in
[`../README.md`](../README.md); how a play is written, in [`../playbooks/README.md`](../playbooks/README.md).

## Files

| File | Owns |
|---|---|
| `server.py` | `Server`: what every doctype standing on a box shares — its Machine's name, `run_playbook`, `Archive`. |
| `fleet.py` | What a named fleet box (Gateway/Ingress) does the same way, plus the fleet-wide settings readers. |
| `ansible.py` / `ansible_runner.py` | Running a playbook against a box, tracked as docs. |
| `runner.py` | `StepHandler`: a doc that runs its step rows one background job at a time (Pathway Update, Server Resize). |
| `tls.py` | Each Geography's zone wildcard: issue over DNS-01, renew, push to that geography's boxes. |
| `datum.py` | datum's write token for one box, minted from Central inside the job (never stored; only when it runs out is, as `datum_token_expires_at`), and the hourly tick that re-runs `vector.yml` on a box whose token has a day left. Also the roster: `push_roster`, every minute, posts one `grove_machine_info{machine, status, vector} 1` per Machine under `grove:region-<region>` to each Region's datum (JSON route), Atlas's shape, with the Region's own kept token (`Region.ensure_datum_token`: asks Central only when it has five minutes left, or datum answered 401); a reader expects rows under `grove:<machine>` only from a Machine whose latest row reads Active with vector 1, so a quiet box that was stopped or terminated is expected and one that is dead, or never shipped, is not. The role itself: `playbooks/README.md` → Vector → datum. |
| `net.py` | Which address one box reaches another on: private inside a Network, public otherwise. |
| `cloud_provider/` | Provider clients, provisioning and reconciliation — [`cloud_provider/README.md`](cloud_provider/README.md). |

`../monitoring.py` stays at the app root: its `targets` endpoint is a URL every Monitoring Agent box holds.

## Doctypes

| Doctype | Owns |
|---|---|
| `Machine` | An on-prem/baremetal/VM box. Cloud GPU pods are **not** Machines — see `Pod`. `gpu_interconnect` (PCIe / NVLink / Mixed) is how its cards reach each other, off `nvidia-smi topo -m`, written by Scan GPUs — a box fact, since one card type ships both ways. Every minute `grove.infrastructure.datum.push_roster` tells its Region's datum the box's status, so a reader knows a stopped or terminated box is expected to be quiet (no per-action hook: a new action needs nothing). |
| `GPU` | One physical card or MIG slice, and the claim on it. `device_id` is what `docker run --gpus` is handed, never `CUDA_VISIBLE_DEVICES`: `GPU-<uuid>` for a whole card, `MIG-<uuid>` for a slice (a slice has no index), or the bare index on a cloud box seeded before any driver existed, until a scan replaces it — stable across a reseat, which the index is not. `held_by` **is** the claim: a column, taken by compare-and-swap, so it cannot outlive the card, cannot name a card that is gone, and disappears when a scan prunes the row. Held for `Draft`/`Provisioning`/`Active`/`Broken`, released on `Inactive`/`Terminated`. How a card is named, and why a rented box identifies its cards by slot: `grove/infrastructure/doctype/gpu/README.md`. The race two placements run: `grove/placement/README.md`. |
| `GPU Type` | One record per card type, and the number every card of it reports. Named for the card the way a person says it (`T4`, `L40S`, `RTX PRO 6000 Blackwell Server Edition`) — the name **is** the display, so nothing is slugified. `ensure_gpu_type()` strips the vendor word to collapse nvidia-smi's `Tesla T4`, AWS's `T4` and RunPod's `NVIDIA T4` onto one record, and records every spelling it meets in `aliases`. An alias is matched **before** the name is derived, which is the only way `NVIDIA H100 80GB HBM3` reaches `H100`. `vram_gb` is seeded by the first scan and never overwritten, so a correction here survives the next one and the whole fleet follows it. |
| `Machine GPU` | The Machine form's grid of its cards (child) — a read-only mirror of `GPU`, rewritten by the same scan that reconciles them, so the two cannot disagree. |
| `Inference Server` | A Machine that serves engines. Everything that reaches the hardware goes through it: a Model Replica talks to its Inference Server, and only the Server knows about a Machine. |
| `Gateway Server` | A Machine that serves customer traffic. Its name is `GROVE_GATEWAY_ID`, its DNS label, and the first part of every request id it stamps. `gateway_store` is the store Setup put its agent on and every deploy keeps — blank only until its first Setup. `is_store_writer` marks the gateways a store is pushed and drained through, tried in name order; the rest only read it. `is_in_maintenance` is the one owner of maintenance: Start/End Maintenance writes it to `config.json` (`config.yml`, SIGUSR1) and reads the box back for up to ten seconds (a read that does not connect is asked again; a box that never answers or kept the old value is an error), and every play that writes that file carries it, so a deploy never flips it. A deploy keeps the gateway on the store it is on. `last_synced_at` is written only on a gateway not on a store; one on a store is stamped on the store. `isolate_caches` is written the same way by **Isolate Caches** / **Share Caches**: pathway then appends `cachesalt` and `cachekey` to its transforms, one prompt-cache partition per team on that box's engines and vendors. Setup chains Vector (`playbooks/README.md` → Vector → datum) and sets `is_vector_setup`; **Install Vector** / **Update Vector** re-runs it; `ship_host_metrics` off keeps the logs and drops the host metrics (a provider's own agent already ships them). |
| `Gateway Store` | The one Redis a Network's gateways share (one per Network, 6379 open to that Network's VPC and nothing outside it, behind a minted password). One in-flight counter per replica is what caps a standalone box across gateways; the store holds their keys too, so a dead one takes them down. Its RDB is shipped every 5 minutes (`backup`: `redis-cli --rdb` over SSH, uploaded from the control plane) into its Geography's backup bucket under `gateway-store/<store>/`, the doc's `last_backup_key` pointing at the newest. Nothing loads a backup back yet (the restore is to be redrafted); a process crash or reboot comes back from the AOF with at most a second lost. Redis comes from Redis's own APT repository, on the line the role's `redis_version` names (`~=8.12.0`: the newest 8.12.x), and runs as `store-redis`: Grove's own unit, config and directories (`/etc/store-redis`, `/var/lib/store-redis`, `/var/log/store-redis`) as the `frappe` account, the packages' `redis-server` unit masked and their directories unused; the doc's `redis_version` is the release the box reported after Setup, the only thing that runs the role (`playbooks/README.md` → A store's Redis). `last_synced_at`: when a Projection tick last confirmed the store holds the desired state, through any writer; the next tick rebuilds only the key buckets saved since it, and a blank stamp rebuilds all. Vector as on a Gateway Server: Setup chains it, **Install Vector** re-runs it, `ship_host_metrics` and `is_vector_setup` mean the same; here the play also lays the redis exporter on the store's password and Vector scrapes it (`redis_*` series: memory, clients, evictions, persistence). |
| `Ingress Server` | One VPC's front door: gateways dial it by name over a verified certificate; it dials replicas privately. Holds no tenant state. `is_in_maintenance` works as on a Gateway Server (both are `fleet.PathwayHost`): its `config.yml` writes the key, and the gateways' requests through it get 503. |
| `Network` | A VPC, subnet, IGW, route table and the proxy, inference and store security groups — creates them, not just references. Ingress rule: boxes in one VPC reach each other (an inference box's 80/443, a store's 6379); from outside it an inference box lets in only its geography's gateways and the agents that scrape it, by public /32. `cloud_provider.reconcile.sync_all` re-syncs every Network's groups each two minutes, writing only where AWS differs; **Sync Ingress Rules** does it at once. The inference front is moving from 443 to plain HTTP on 80 — the hop is inside the fleet and nothing verified the self-signed certificate — so the rules open both (`FRONT_PORTS`) until every box has moved, then 443 goes; a proxy box keeps 443, it faces customers and holds a real certificate. |
| `Region` | A provider's region code and its label, and which gateways are in it. Belongs to one `Geography`, fixed once a Network or Machine names it. **Monitoring** tab: the region's datum, as two routes — `metrics_url` (remote write, for the Monitoring Agent and Vector alike; no fleet-wide fallback) and `logs_url` — that every box here pushes to, and `central_region`, Central's name for the region that datum belongs to (Grove's codes and Central's are different lists), which is what Grove asks Central to mint tokens for. Also keeps the roster's own datum token (`datum_token`, `datum_token_expires_at`; `ensure_datum_token` re-mints with five minutes left). |
| `Geography` | A residency boundary (`in`, `eu`), its public `endpoint`, and its own hosted zone (`fleet_zone`) with that zone's wildcard certificate (Issue Fleet Certificate; renewed daily per geography, pushed only to its boxes). Every box in it is named `<box>.<fleet_zone>`, and the endpoint is one label under that zone or the zone itself (the certificate covers both), checked for hostname shape only and blank until the operator fills it. Its gateways share one DNS set at that endpoint, are pushed only routes from inside it (replicas, ingresses and vendors with this `geography`, and every pod when it is the Pod Geography), and 403 a key pinned elsewhere. One Geography is **Is Default** (ticking it on one unticks the rest): a Grove API Key saved without a geography is pinned there. **Store Backups** tab: its own bucket + Put/Get key for Gateway Store RDBs (blank = no backups here). Every box carries a read-only `geography` copied from its Region (Machine sets it in validate; the rest `fetch_from`). Still leaves the geography: token counts to this site, and every key hash and team name to every gateway. |
| `Cloud Provider` | One account and its credentials. |
| `SSH Key` | The keypair a box is provisioned with. |
| `Monitoring Agent` | The scraper. A box's exporters only listen; this is what polls them. |

### Operations — what was done to a box

Append-only. Never read to decide anything; read to find out why.

| Doctype | Owns |
|---|---|
| `Pathway Update` | Deploys Grove Settings' Pathway Release (and Repo, both copied read-only at insert) to chosen servers, one `Pathway Update Server` row (child) at a time. The Gateways / Ingresses boxes are set once: they add every Active server of that type at insert and limit which types rows may name; rows can be added or deleted whenever it is not running. Never starts by itself. **Start** checks nothing else is running, the pin still matches, the Pending servers are Active and the release is published, then runs `_deploy_agent` per Pending row through `runner.StepHandler` — which records `agent_version` on the server. A failed deploy stops it (traceback on the doc, Error Log, notification) and puts the failed server (gateway or ingress) in maintenance to be debugged — End Maintenance on it when done; **Continue** carries on past failed rows, and re-adding a failed server as a row retries it. **Stop** takes effect between servers, never mid-deploy. Start/end times on the update and on each row. |
| `Server Resize` | Moves one Gateway Server or Gateway Store onto another instance type, one `Server Resize Step` row (child) per background job through `runner.StepHandler`. Made on its own form or from the server's **Resize Server** button, then run with its own **Start** button (Pending only); both show the box's current type with its architecture, vCPUs and RAM and pick the new one from the types it can move to (`NamedHost.resize_options`: same architecture, virtualised, current generation, EBS-rooted, offered in the Network's zone, no GPUs; the provider's list is cached six hours per provider/region/architecture/zone, the current type read live; `instance_type` is an Autocomplete fed by it); any server but a Terminated one (the form's `server` picker lists only those); insert refuses a type of another architecture (the image is fixed), bare metal, the same type, a box not running, a gateway memory limit the new RAM cannot hold, and a second resize of the same server. A gateway: maintenance → wait for the box to say maintenance on and `in-flight` 0 (5 min cap; a poll that does not connect is asked again) → `stop.yml` (pathway) → Machine stop → wait Stopped → type changed at the provider → Machine start → server Active again on its addresses (DNS, health check, security groups) → wait for pathway → `memory.yml` with a restart → maintenance off. A store: the same around `stop.yml` (redis) and `ping.yml`, with every Active gateway on it put in maintenance first, one row each, and lifted last; a gateway already in maintenance is Skipped and stays in. During the window the server reads Broken (a stopped Machine's dependents always do). A failed step fails the resize (traceback on the doc, Error Log, notification), then starts the box again on whatever type it has, puts the server back and lifts the maintenance this resize set once pathway answers (capped); what could not be undone is appended to `error`. The type is never reverted. |
| `Ansible Play` | One playbook run. Its status is written by the callback and so is best-effort; what a caller acts on is Ansible's own rc, never this. |
| `Ansible Task` | One task in it, created as it starts — including handler tasks, or a failure inside a handler produces a play that failed with no row saying why. |

## Conventions

- **Box names are generated, never typed** (`grove/naming.py`): a Machine is `<prefix><n>-<region>`,
  the prefix from its Machine Type (`NAME_PREFIX`), counted per region out of `tabSeries`, and the
  server doc on it takes the Machine's name. The first label carries the region as a suffix rather than a
  namespace — `*.<zone>` covers `gw1-ap-south-1.<zone>` and nothing deeper — and a box whose Geography has a zone is
  named with it (`gw2-ap-south-1.<zone>`), so its domain shows at a glance. Request ids and agent ids carry only the
  first label (`short_name`); boxes named before this keep their short names.
- **A cloud resource id lives in a read-only `Data` field**, written with `db_set`, and its creator is
  guarded by `if self.<id>: return` (see `Network.create_network`). That is what makes provisioning
  re-runnable.
- **A doctype standing on a box extends `Server`** (`grove/infrastructure/server.py`): its name is its
  Machine's (a name passed on insert wins), it calls `run_playbook("x.yml")` — never
  a path, a server type or a Machine — and it is retired with `Archive`. Archive refuses while
  anything depends on the box: each doctype lists its own dependents in `archive_blockers`
  (replicas on an Inference Server, boxes routed through an Ingress, targets of a Monitoring Agent,
  the last gateway of a region that still serves, gateways still on a Gateway Store), then a cloud Machine is terminated, whose
  cascade already marks the row Terminated and drops its DNS. An on-prem box only has its row retired.
  A cloud Machine launches with Termination Protection on; while the provider reports it on, Terminate
  (and so Archive) refuses before anything is released. Its button turns it off.
  A bare-metal Machine that is gone is retired with its own `Terminate`: no provider call, just the
  same cascade. An Inference Server going Terminated takes its replicas with it — the box is
  gone, so no teardown play runs and only their rows (status, port) are retired.
- **A new Inference Server takes the Network's only ingress and only monitoring agent** when there
  is exactly one of each (`default_to_network_singletons`); two or more stay an operator's pick.
- **An Inference Server is fronted by an ingress or is Standalone.** Standalone skips the ingress:
  gateways dial `<short name>.<its geography's zone>` (DNS record follows the flag), its nginx serves the fleet
  wildcard, and renewals reach it through `tls.push_to_proxies`. Neither saves with a banner; Setup refuses.
