# `doctype/` — what each record owns

Some thirty doctypes, three families. The useful question about any of them is **which state does this
one own**, because Grove's rule is that state has exactly one owner and everything else derives.
What a call cost — counters, prices, caps, usage records — is the [`billing/`](../../billing/README.md)
module's doctypes. A box and what it stands on — machines, servers, networks, geographies, the plays
and resizes run on them — is the [`infrastructure/`](../../infrastructure/README.md) module's.

## Serving — what actually answers a request

| Doctype | Owns |
|---|---|
| `Model` | A model as one provider record serves it. The doc name is a hash; **Model Key** (`<provider name>/<model id>`) is what a caller sends, the route key and the usage bucket — set off the Model ID linked at creation and frozen. **Provider** links one record; a vendor with a record per Geography has a Model doc per record, all under one key, each with its own Upstream Model ID and Model Pricing (unique on provider + model id). **Geography** is fetched from the record, so two docs of one key tell apart in a list and a link picker. The provider's name is read off the record, never stored on the Model; the save refuses a link whose name is not the key's prefix, so it can move only between records of the same name. A Link anywhere means the doc; the key means the id — every Link holder (pricing, deployment, replica, pod, grant row, discrepancy) carries the key as a fetched column. One under the Self Hosted provider names an HF repo — that is what an engine serves, under the key, and what the S3 mirror is filled from; one a vendor serves names none, because there is no engine to start. `published` is the serving gate, ticked by hand: the gateways hold a route only while it is set. The save refuses a model with no Enabled Model Pricing, or with nothing serving it — a live deployment, a running pod, or a front on its own provider record. Nothing publishes on its own; a model nothing serves any more is unpublished on its own. Not an access gate. **Load Pricing** inserts the rates `catalog/catalog.json` holds for the key as a Disabled Model Pricing, while none names the doc. |
| `Model ID` | One model id (`deepseek-v4.1-flash`, `claude-sonnet-5-5`): what follows the provider's prefix in a Model Key, one record per id whoever serves it. The name, slugified once at insert (`Claude Sonnet 4.5` → `claude-sonnet-4.5`, no slash), and a **Display Name** (`DeepSeek V4.1 Flash`), what a customer's dashboard shows for it — `api.catalog.available_models` sends it as `display_name`, the id when blank. The record is where what is the model's and not one provider's goes. Every Model links one (`model_id`), so a Model cannot name an id the site has no record of; `ensure_model_id` makes the record (and fills a blank Display Name from the catalog's) for the catalog, a Fetch Models pick and the `create_model_ids` patch. |
| `Denied Tool` | One tool a vendor would run on its own side and bill outside the token counts, which the gateway refuses to send it: a `tools[].type` (`web_search_20250305`) or a top-level request field (`web_search_options`), under the vendor's **Provider Name**. The name is the pair. Rides every provider route row of the vendor as `denied_tools`; a request that names one is a 400 at the gateway before the dial. Keyed by the name and not a Model Provider link: the list is the vendor's, and a vendor has a record per Geography. Delete the row once the tool is priced, and drop it from `catalog/catalog.json` too, or the next migrate seeds it back. |
| `Model Provider Key` | One credential of a vendor, a document of its own linked to one **Model Provider** record (set once; the record's form lists its keys under Connections). Its secret is set once too (Frappe's own set-once check, which compares the masked values, so a new secret of the same length is not caught): the name is the id the gateways count under, so a rotated secret is a new key and the old one is disabled. **Used For** says its job: `API Calls` (pushed to the gateways), `Billing` (held for the vendor's billing API alone and pushed to no gateway — an admin key that cannot serve a request), or `API Calls and Billing` (one secret that does both); `ModelProvider.gateway_keys` and `.billing_keys` are the two readers. The name is the id the gateway picks, rotates and counts under; the secret itself is never named anywhere. **Title** is mandatory and one per provider (a unique index): it is what the usage page and every link to the key show. No role may delete a key (the doctype grants no delete), since its stats link it; **Disabled** is how a key is retired: it is used for nothing, pushed to no gateway and read no billing with. |
| `Model Provider Header` | One header the gateway adds to every request to the parent record's fronts (child of Model Provider): `header` and `value`, sent as is. A name is an RFC 7230 token listed once, a value one line; `Authorization` and `x-api-key` are refused, since the credential comes from Keys and is set after these. Rides every provider route row of the record as `headers`. |
| `Provider Key Stats` | What one key answered on one gateway store since the pull before, in `stats` (indented JSON, shown as code), by the 6-hourly pull and never updated; a key is its link (**Model Provider Key**, `key_id`) beside its Model Provider, a store its link. The key's Title is read off the key, never copied here. The gateway clears its counters as it answers; a store that did not dial the key leaves no row. |
| `Model Provider` | Who serves a model. The one flagged **Self Hosted** is ours: blank-provider Models are named under it, and only its models can be deployed. Every other provider is a vendor, dialled through its URL fields: with a **Base URL** (and at least one enabled `Model Provider Key` used for API calls), its published models route straight to the vendor and nothing is ever deployed for them. **Provider Name** is the namespace every model under it is named in, set once; the doc name is a hash. A Select of the vendors pathway knows (`vendor.known`: anthropic, baseten, deepseek, morph, openai) and `frappe` for ours — a gateway refuses a push naming any other, so a new vendor ships in pathway first and is added to the field's options with it. **Display Name** (`OpenAI`) is what a customer's dashboard shows for the provider (`api.catalog.available_models` sends it as `provider_display_name`, the name when blank); it is the name's, so a save writes it on every record of the name and a new record takes it. **Extra Headers** (`Model Provider Header` rows) are added by the gateway to every request to this record's fronts (`anthropic-beta`, a vendor's own); the credential and the version header are the gateway's and win over them. A vendor has one record per `Geography` it processes in, all under the same Provider Name (unique together), and each gateway dials its own geography's record — so `openai/gpt-5` is one key everywhere and a regional front (eu.api.openai.com) is a second record, not a second provider. A model routes in a geography when it has a doc under that geography's record: the catalogue is per record, so a regional upstream id or price is that doc's own. "EU" differs by vendor (OpenAI and Mistral include EEA/CH; Vertex is EU member states only). **Fetch Models** lists the vendor's own `/v1/models` (OpenAI front first, else Anthropic's) and adds the ticked ids as unpublished Models under the record. **Zero Data Retention** says the provider keeps nothing of a request once it is answered — a vendor's arrangement, ticked by hand; always on for the Self Hosted one — and `api.catalog.available_models` carries it per model, so a team's dashboard shows which providers keep nothing. |
| `Model Deployment` | The logical service: one Model on one hardware shape. Owns the image, the GPUs-per-replica, and the tuning every replica of it runs. Named `MD-{#####}`, counted — several deployments of one model are normal (a second **shape**, or a rollout running old and new side by side). The name carries neither the model nor the shape: `gpus_per_replica` is editable while a name is not, so `4xh100` would go stale the first time someone re-shaped it. Deliberately **not** region-scoped: `deploy:<model>` is global, so replicas in different regions already stand in for each other, and one deployment rolls a model out everywhere. `placement_policy` names which scorers `find_placement` ranks boxes by (`grove/placement/`) — it only ORDERS boxes that could already take the replica, never admits one that could not. |
| `Model Replica` | One **replica** of a Model Deployment: which box, which cards, which port. Named `<model id>-<region>-<server>-<n>` (`qwen3-8b-ap-south-1-inf3-00007`). Re-derives its arguments at deploy time from the Engine its deployment builds — a `custom` image runs its own entrypoint and is gated at the box's proxy instead of by a key it does not enforce. Carries tuning where it **overrides** its deployment: blank or 0 there means inherit. `kv_cache_dtype`, `gpu_memory_utilization`, `max_num_seqs` and `attention_backend` are **prefilled**, so a new replica starts as an explicit override and editing the deployment will not move it — clear the field to hand ownership back. Migrated replicas were blanked, so they inherit. Takes as many cards as its deployment declares — replicas of one deployment are interchangeable, which is what makes `replicas x capacity` arithmetic. |
| `Model Replica GPU` | Which GPUs that replica was **given** (child) — the run script's `--tensor-parallel-size` and CUDA pinning. Not the claim. |
| `Pod` | A standalone RunPod vLLM instance. Fully self-contained — its own spawn/sync/restart/terminate, and it registers its own endpoint with the gateways of Grove Settings' `pod_geography` — every pod serves in that one geography (blank routes none). Sends its **stored** `serve_command`, so it must be saved before it is re-spawned. `provision_at` / `terminate_at` (Up From / Down From) are a daily window the every-minute tick (`infrastructure/cloud_provider/schedule.py`) keeps it inside — spawned once per day while inside and unprovisioned, terminated while outside and live; a spawn re-asks the provider `provision_retries` times (the create call only); every lifecycle call leaves a `Pod Activity` row. |
| `Pod Env` / `Pod Port` | That pod's environment and its port pool (children). |
| `Engine Image` | The container image an engine is spawned from, and what only the image knows: its `engine_kind`, and for a `custom` one the warmup request (path + body) that proves it serves. Both placements read them, so the same image warms up the same way wherever it runs. |
| `Engine Image Provider` | A registry and the credentials to pull from it. One record per registry. |

## Tenancy — who may call what

| Doctype | Owns |
|---|---|
| `Grove Team` | A control client's team — Central's (`TEAM-00520` is the doc name) or Press's (`Press Team`) — named by the client's id for it. Every `grove.api` call names the team by it, and `api.teams.provision_team` upserts by it. Grove keeps nothing else about who the team is — no email, no login; contacts are the client's. What is the team's is its `tier` and the house rules, set by Central (`api.teams.update_team`; an edit in Desk is overwritten on the next sync; the tier is picked in Desk only when the team is made, read-only after). A tier change arrives by Central's Frappe Webhook at `api.teams.team_webhook`, a guest endpoint that checks the body's HMAC against the control user's `api_secret` (`X-Grove-Control-Key` names the user by its `api_key`); the body carries `observed_at`, when Central read it, kept as `last_reported_at`, and one not newer is a retried or reordered delivery, ignored. A team Grove does not know is ignored too, since AI is off for it. The Tier names `spend_limit` (USD a month), which what its keys spent this month and the live caps together stay within (`pricing.committed`), and the rate limits the team runs under per model, counted on the gateway for the team as a whole however many keys it holds (blank tier: the default tier in Grove Settings). A team holds as many keys as it likes. `suspended`, set when an invoice goes unpaid and pushed as `limited` on the team's record, which refuses every key of the team; while it is set a control client's mint, cap change and revoke are refused (`api.keys.changes_keys`), and `api.teams.archive_team`, how a client closes a team, still revokes every live key (`revoke_keys`); the form's **Suspend Keys** button (`set_suspended_at_grove`) sets it too, with `suspended_at_grove` beside it to say the hold is Grove's, which Central's sync cannot lift (`validate` keeps `suspended` on while it is ticked). Resume Keys clears both; Central puts its own back on its next sync. `key_cap_window`, what each of its keys' caps counts — **Monthly**, this UTC month's spend, or **Total**, everything since the key was minted, so a spent key stays spent (a trial team) — operator-set when the team is made and fixed after (the gateway keeps a different counter per window, so a change would restart every key's count; a control client's insert naming Total is refused in `before_insert`, so the teams it makes are Monthly), pushed on every key of the team as `budget_window`. `cap_message`, what the gateway answers at 402 once one of its keys' caps is spent, in place of its own "key credits exhausted" — a trial team's "upgrade to go on"; operator-set in Desk, pushed on the team's record; blank keeps the gateway's text, and so does a suspended team's key, that hold not being the cap's. A Total team has no spend limit: its caps are for life, so what the month has spoken for binds nothing (`needs_cap_check`, `api.keys.update_caps` skip the check, `figures` reports `spend_limit` null), and the revokes bound it instead. `log_payloads`, whether the gateways store the prompts and outputs of the team's keys, on by default; the team sets it from Central's console (`api.teams.update_team`), and `api.usage.figures` reports it. What its keys may call lives here, not on the key (a key is revoked and minted again at will): `model_groups`, `allow` and `deny` (`Model Group Row` and `Grove Model Row` tables). A Model Group and a vendor model are one geography's and reach only the team's keys in that geography; a model of ours reaches every key (`access.team_grants`, `access.reaching`; `snapshot.effective_keys` stamps each key's slice on its record, so the gateway reads the key alone). A new team is put in every geography's default group (`before_insert`); a model in both Allow and Deny is refused. Cap and geography stay on the key. `limits` and `key_limits` (Limit Overrides, operator-set in Desk) are the team's own `Model Limit` rows, laid over its tier's table of the same name (`access.limits_in_force`): a row stands in for the tier's on the same model, metric and window, the tier's other rows hold, and a row at 0 lifts the limit there. Only the one of its tier's scope is shown and in force: `limit_scope` on the team is a read-only virtual field answering the tier's (`access.limit_scopes`; the default tier's for a team with none). The gateway holds a team record (`snapshot.effective_teams`, the push's `teams` section): `limited`, `log_payloads`, `cap_message` and its rate limit rows, sent as `limits` or as `key_limits` by its tier's scope, read beside each of the team's keys, so a suspension or a tier's rows are sent once per team. The record is built per geography: a gateway is sent the rows that hold in its own (`access.limits_reaching`). Its grants still ride each key, sliced by the key's geography, and so does `budget_window`: it names which of the key's own counters the cap reads. A site from before this doctype is moved by the `move_grove_users_to_central_teams` patch: one team per Grove User (named by its reference, else its old name), each key given the user's geography, groups, grants and limits, and its spend from the records; every key starts at a cap of 0. Renamed from `Central Team` by `rename_central_team` (2026-10-22): a team at Grove is any control client's. |
| `Tier` | What a team on it may do, named by Central's trust tier label (`Beginner`, `Growth`, `Intermediate`, `Advance`, `Power`, `Elite`): `spend_limit` (USD a month across the team's keys, their caps and what they spent; 0 lets no cap be set) and `limits` rows of `Model Limit`, the rate limits the team runs under per model, counted on the gateway for the team as a whole (`lim:team:<team>:<model>:…`) however many keys it holds (a row linking no model is every model, each on its own window; a row linking one stands in for it there, in that model doc's geography; no rows is explicit, uncapped). A row at 0 is no limit on its model, metric and window: naming a model, it lifts the blank row there alone. `limit_scope` (Limits Count Per) says who the limits are counted for, one or the other, each with its own table: **Team**, the rows of `limits`, or **Key**, the rows of `key_limits`, counted under each key of the tier's teams on its own (`lim:key:<prefix>:<model>:…`; a trial tier, where every key is another customer). The table not picked is hidden and not in force, and an empty `key_limits` under Key is uncapped like any tier with no rows; the scope is tuned in Desk, and the catalog writes its rows into whichever table is in force (`seed.sync_tier`). Until a tier could say, the gateway counted per key, so the `move_tier_limits_per_key` patch moves every existing tier's rows to `key_limits` and sets it to Key. A team's own rows are laid over the tier's, row by row. Central names a team's tier (`Grove Team.tier`, through `api.teams.update_team`). `spend_limit` is Grove's, tuned in Desk; the rows are the catalog's — `catalog.json` ships them and `seed.sync_tier` rewrites them on every migrate, so a row is edited in the file, never in Desk. The file names a model by key, and by `geography` when the row is one geography's; the load links every doc of that key there (`seed.tier_rows`). `Grove Settings.default_tier` is what a team with no tier runs under and what a tier Central names before Grove has one is cloned from (`ensure`; no default: the hard-coded rate limits, spend limit 0). An edit reaches every team on the tier at once (the save forgets each one's cached figures, so its console shows the new limits), and the gateways at the next push, on each team's record. When Central renames a label, `api.teams.rename_tier` renames the Tier and every link follows; a label Grove never saw is nothing to rename, and a name Grove already has is left alone, not merged. A tier a team names cannot be deleted. System Manager edits; Grove Control reads, creates and renames. |
| `Model Group` | A named set of models in one **Geography** (required, set once; left blank it is the default one). A vendor model in it is that geography's doc, so the row is the doc and price its members reach; a model of ours goes in any group, since it serves wherever a replica runs. Membership lives on `Grove Team`, which lists the groups it is in, and on a `Grove API Key` on top of its team's — there is no member table. A team's key reaches the union of the team's groups of the key's geography and its own. The one ticked **Is Default** (one per geography) is put on every new team that names no group of its own, so whoever provisions a team or mints a key sends no model list; a team taken out of every group reaches nothing until one is added. The gateways still get every group as a key list. `api.catalog.available_models(team, geography)` lists what the team's keys there reach (`access.get_reachable_models(team, geography)`: the team's groups there and its Allow that reaches there, less its Deny), for a control client to show; a key's own groups are the key's alone and not listed. |
| `Grove Model Row` | One model in a grant (child): the doc, and its `model_key` fetched beside it — the id a caller sends, what the gateway matches and what the projection reads without a join. Off the grid, since the doc's title already names it. |
| `Model Group Row` | One group a team, or a key on top of its team, is in (child). |
| `Model Limit` | One rate limit on its parent (child of a Tier, or of a Grove Team for its own laid over the tier's): `model` (blank: every model, each counted on its own; a Link to one Model doc: that model alone, standing in for the blank row on its metric and window, and only where the doc is — a vendor's doc is one geography's, so the row reaches that geography's gateways alone, while a model of ours reaches them all; `model_key` is fetched beside it), `metric` (`requests`, `total_tokens`), `window` (`1m`, `1h`, `1d`, `1M`, reset on the UTC clock) and `value` (0: no limit there). One row per model doc, metric and window within a table (`access.validate_limit_rows`). On the wire `metric:window:value[:model_key]`, the model last so a key holding a colon still splits. The gateway refuses a push carrying a metric or window it does not know, so a new option ships in pathway first. |
| `Grove API Key` | One credential and the whole policy behind it, unique by `key_hash` (the index is what makes the 192 random bits' uniqueness a guarantee, and what every lookup by hash uses). It belongs to one `team` (Grove Team) and works in one `geography`, both set once: left blank it is the default Geography, and gateways elsewhere answer 403 — its spend and rate counters live on that geography's store, which is what lets that store gate it exactly; a team spans geographies by minting a key in each. What it may call is its team's (`Grove Team.model_groups`, `allow`, `deny`), sliced to the key's geography: a Model Group and a vendor's doc reach the keys of their geography, a model of ours every key; whoever mints a key sends no model list, or names groups of the key's geography it is in on top of its team's (`model_groups`, `provision_key(model_groups=)`: a product's trial catalog). `cap` is what it may spend over its team's `key_cap_window`: pushed as `budget` with `budget_window`, and the gateway, which counts the key's spend per UTC month or in one total since the mint, refuses it at 402 once that reaches the cap; 0 until a cap is set and refused until then, and across the team's keys what the month has spoken for — each live key's cap or its month's spend, whichever is more, plus what revoked keys spent (`pricing.committed`) — never exceeds the team's `spend_limit` (checked on a raise and a mint with a key's month as the records or what its box counts, whichever is more, `usage.peek_team`; the team row is taken ahead of the key's own and the boxes read under it, so two raises queue rather than deadlock; so a lowered limit stops no key, a key can always be minted at 0, and a revoke frees its cap but never its spend). What it spent this month is read off the records and corrections (`pricing.month_spent_by`), never stored. It holds no rate limit rows of its own: they ride its team's record, its tier's rows with the team's own laid over them (`access.limits_in_force`; the default tier's for a team with none, else `access.DEFAULT_LIMITS`, 20 requests and 100 000 tokens a minute, per model), sent as `limits`, counted for the team as a whole (`lim:team:<team>:<model>:…`), or as `key_limits`, counted for this key alone (`lim:key:<prefix>:<model>:…`), by its tier's `limit_scope`. It is a sorted `metric:window:value[:model_key]` list, counted per Gateway Store: requests as they are admitted, tokens once the answer reports them, and a request over one gets 429 with `Retry-After` naming the model and whose limit it was (the Insights dashboard's Rate Limited Keys table counts those per key and UTC day, off the access lines Vector ships); a tier with no rows is uncapped. `title` is a label to tell a team's keys apart, set once at the mint, and a unique index on (title, team) makes it used once per team, ever, revoked keys included (Press titles a trial site's key by the site, and a site must never get a second); blank is no title, stored as NULL, which the index never counts as a twin. `expiry` is the rule it retires by, set at the mint (`provision_key(expiry=)`: Never, or 1, 7, 14 or 30 days) and fixed after, and `expires_at` the moment that names; `revoke_expired`, hourly, revokes every live key past it and the next tick prunes it off the boxes, so an expired key answers for an hour at most. With `expiry_from_first_use` (set on the doc at insert; `provision_key` does not take it) the rule counts from the key's first usage record instead: `expires_at` stays empty until `grove_api_key.start_expiry`, called as `pathway/reconcile.py` lands the records, sets it once, so a key minted ahead and held in stock — Central's trial pool — does not age on the shelf. `extend_expiry(days)` on the doc moves `expires_at` by `days` from now or from its moment, whichever is later; a key without a moment is left as it is, a revoked one refused; no endpoint calls it. `figures` lists all three. `api.keys.transfer_key(team, key, to_team, title)` hands a key to another team — what Central sends when a trial converts, so the secret the customer's server holds keeps working: the team and the title move and the trial's rules go (its own groups cleared, its expiry lifted to Never), in one save, which a `Key Transfer` row records and the next tick re-pushes; cap and geography stay as minted; counted against the new team like a mint (its cap within a Monthly team's spend limit); a key the receiving team already holds is answered as it is; one between two teams of the same cap window is refused (the box keeps a key's spend under one field per window, so it would follow the key). The box closes the old team's books at that push (a set-aside stamped `team`, landed under it by `pathway/usage.py`), so what the key spent before the move stays the old team's, and `month_spent_by("api_key")` sums only the records under the key's team now. The secret is handed out once, by `api.keys.provision_key`; `api.usage.figures(team)` lists a team's keys masked to the prefix and four characters (never the end; `masked`, kept on the key at mint, so a listing decrypts nothing), each with its geography and endpoint, cap and `month_spent` (`spend.limits` is the team's limits in force), the `key_hash` that narrows `api.usage.usage`. `api.keys.update_key` changes the cap; `api.keys.update_caps` sets several of a team's caps in one call, lowers first, refused whole when the total would pass the spend limit (a batch that raises nothing is checked against nothing); `api.keys.revoke_key` takes `team` and the key's name, refused when another team holds it, and `api.keys.revoke_keys(team, keys)` several in one call, refused whole for a key the team does not hold (an archive); a revoked key stays revoked, mint a new one. The gateway's `/v1/key/balance` answers a key its own cap less its window's spend, nothing of the team's. |
| `Grove Settings` | Single. The fleet-wide knobs: Pod Geography (where every pod serves), Default Tier (what a team with no tier runs under, and what an unseen tier name is cloned from), Usage Retention (how long a gateway keeps acked usage; rendered into its `config.json`), DNS provider (owns every geography's zone), ACME email, pathway release and repo, monitoring (the Service Discovery Token every agent presents: at least 16 URL-safe characters, checked as it is set), the weights bucket and its two key pairs (engine read; Mirror write), and Central's URL and Central Token — a secret of Grove's own, sent as `X-Grove-Token`, whose SHA-256 Central's AI Settings holds — with which Grove mints each box's datum token (`grove.infrastructure.datum`). |

## Logs — what happened, and to which box

Append-only. Never read to decide anything; read to find out why.

| Doctype | Owns |
|---|---|
| `Pathway Sync` | One push run. Its list view holds **Force Sync All** — the fleet-wide force-push. |
| `Pathway Sync Row` | One TARGET in that run (child) — names the **doctype as well as the box**, because the two planes take different pushes. |
| `Gateway Deletion` | One Redis record a box still holds and should not. Every other push is an UPSERT, so without this a revoked key would keep working. |
| `Key Transfer` | One hand-over of a `Grove API Key` between teams: the key, the team it left, the team it went to and the title it had before, with `creation` as when and `owner` as who. Written by `GroveAPIKey.transfer` in the save that moves the key (a refused move leaves none), kept for good, never read to decide anything. The Usage page tags a moved key's row with where it came from, lists it marked Transferred under the team it left (with or without usage in the period) and offers that team the keys it handed over, since their usage before the move stays under that team. Moves from before the doctype were filled in from the Versions they left (`patches/v1_0/log_past_key_transfers.py`); a key's saves leave no Version since, change tracking being off on `Grove API Key`. |
| `Pod Activity` | One lifecycle call on a Pod — spawn attempt, restart, stop, start, terminate — with its trigger (button or tick), outcome, duration and the provider's error. Written by `PodProvisioner`, never read to decide anything. |

## Conventions these all follow

- **A replica's name says what it serves and where** (`grove/naming.py`):
  `<model id>-<region>-<server>-<n>`, e.g. `qwen3-8b-ap-south-1-inf3-00007`. The region goes in as
  its provider codes it — no shortening rule, since `ap-south-1`, `asia-south1` and `southeastasia`
  share none. The box contributes only the part of its name that is not the region (`inf3`), and
  the number comes out of the same `MD-` series the old `MD-00007` names used — kept as `MD-`
  through the rename because it is a counter key, not a label. The name is also the engine's
  container name (`vllm-<name>`) and its path on the box's proxy, so it is never renamed after
  insert.
- **A deployment's name is `MD-{#####}`** (`grove/naming.py`), off the SAME `MD-` series, so one
  number is handed out once and an `MD-` name never means two things — replicas predating the
  descriptive format are still named `MD-00010`, and a route row's `deployment=` carries a replica
  name. It says neither the model nor the shape: `gpus_per_replica` is editable and a name is not.
- **A connections badge counts live rows.** `grove/notifications.py` names the "open" filter per
  doctype — a Network's Machine link and a Model Deployment's Model Replica link show the Active
  ones, a Pod's Activity link the failed ones — and the total stays in the count.
- **Long buttons enqueue.** `frappe.enqueue_doc(..., queue="long")`, and the worker method carries
  `@failure.reports_failure` so a crash marks the doc Broken with the reason on it.
- **A button that changes a box or a record confirms first.** `grove.confirm_call(frm, message,
  method)` (`public/js/confirm_call.js`); the message says what happens. Reads (Ping, Check State,
  GPU Memory, AWS Sync) stay one click.
- **A child table row names the thing it is about.** Frappe silently drops an `append()` key that is
  not a field, which is how a row full of numbers with no server on it got shipped once.
