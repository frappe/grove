# `doctype/` — what each record owns

Thirty-odd doctypes, four families. The useful question about any of them is **which state does this
one own**, because Grove's rule is that state has exactly one owner and everything else derives.
What a call cost — counters, prices, caps, usage records — is the [`billing/`](../../billing/README.md)
module's doctypes.

## Infrastructure — a box, or a thing a box needs

| Doctype | Owns |
|---|---|
| `Machine` | An on-prem/baremetal/VM box. Cloud GPU pods are **not** Machines — see `Pod`. `gpu_interconnect` (PCIe / NVLink / Mixed) is how its cards reach each other, off `nvidia-smi topo -m`, written by Scan GPUs — a box fact, since one card type ships both ways. |
| `GPU` | One physical card or MIG slice, and the claim on it. `device_id` is what `docker run --gpus` is handed, never `CUDA_VISIBLE_DEVICES`: `GPU-<uuid>` for a whole card, `MIG-<uuid>` for a slice (a slice has no index), or the bare index on a cloud box seeded before any driver existed, until a scan replaces it — stable across a reseat, which the index is not. `held_by` **is** the claim: a column, taken by compare-and-swap, so it cannot outlive the card, cannot name a card that is gone, and disappears when a scan prunes the row. Held for `Draft`/`Provisioning`/`Active`/`Broken`, released on `Inactive`/`Terminated`. How a card is named, and why a rented box identifies its cards by slot: `grove/grove/doctype/gpu/README.md`. The race two placements run: `grove/placement/README.md`. |
| `GPU Type` | One record per card type, and the number every card of it reports. Named for the card the way a person says it (`T4`, `L40S`, `RTX PRO 6000 Blackwell Server Edition`) — the name **is** the display, so nothing is slugified. `resolve()` strips the vendor word to collapse nvidia-smi's `Tesla T4`, AWS's `T4` and RunPod's `NVIDIA T4` onto one record, and records every spelling it meets in `aliases`. An alias is matched **before** the name is derived, which is the only way `NVIDIA H100 80GB HBM3` reaches `H100`. `vram_gb` is seeded by the first scan and never overwritten, so a correction here survives the next one and the whole fleet follows it. |
| `Machine GPU` | The Machine form's grid of its cards (child) — a read-only mirror of `GPU`, rewritten by the same scan that reconciles them, so the two cannot disagree. |
| `Inference Server` | A Machine that serves engines. Everything that reaches the hardware goes through it: a Model Replica talks to its Inference Server, and only the Server knows about a Machine. |
| `Gateway Server` | A Machine that serves customer traffic. Its name is `GROVE_GATEWAY_ID`, its DNS label, and the first part of every request id it stamps. `gateway_store` is the store Setup put its agent on and every deploy keeps — blank only until its first Setup. `is_store_writer` marks the gateways a store is pushed and drained through, tried in name order; the rest only read it. `is_in_maintenance` is the one owner of maintenance: Start/End Maintenance writes it to `config.json` (`config.yml`, SIGUSR1) and reads the box back, and every play that writes that file carries it, so a deploy never flips it. A deploy keeps the gateway on the store it is on. `last_synced_at` is written only on a gateway not on a store; one on a store is stamped on the store. |
| `Gateway Store` | The one Redis a Network's gateways share (one per Network, 6379 open to that Network's VPC and nothing outside it, behind a minted password). One in-flight counter per replica is what caps a standalone box across gateways; the store holds their keys too, so a dead one takes them down. Its RDB is shipped every 5 minutes (`backup`: `redis-cli --rdb` over SSH, uploaded from the control plane) into its Geography's backup bucket under `gateway-store/<store>/`, the doc's `last_backup_key` pointing at the newest. **Restore** (Danger) loads a store's latest backup — its own, or the Terminated store this box replaces, same Geography only — through a side Redis and `REPLICAOF` (`restore.yml`; afterwards this month's spend counter on each live key is raised to what Grove has billed it where the snapshot has less), drops the `usage:<key>:<day>` buckets a drain newer than the snapshot already billed (`landed_since`), every transient key and the projection hash; `spent` rolls back with it. For a lost disk only: a process crash or reboot comes back from the AOF with at most a second lost. `last_synced_at`: when a Projection tick last confirmed the store holds the desired state, through any writer; the next tick rebuilds only the key buckets saved since it, and a blank stamp rebuilds all. |
| `Ingress Server` | One VPC's front door: gateways dial it by name over a verified certificate; it dials replicas privately. Holds no tenant state. `is_in_maintenance` works as on a Gateway Server (both are `fleet.PathwayHost`): its `config.yml` writes the key, and the gateways' requests through it get 503. |
| `Network` | A VPC, subnet, IGW, route table and the proxy, inference and store security groups — creates them, not just references. Ingress rule: boxes in one VPC reach each other (an inference box's 80/443, a store's 6379); from outside it an inference box lets in only its geography's gateways and the agents that scrape it, by public /32. `cloud_provider.reconcile.sync_all` re-syncs every Network's groups each two minutes, writing only where AWS differs; **Sync Ingress Rules** does it at once. The inference front is moving from 443 to plain HTTP on 80 — the hop is inside the fleet and nothing verified the self-signed certificate — so the rules open both (`FRONT_PORTS`) until every box has moved, then 443 goes; a proxy box keeps 443, it faces customers and holds a real certificate. |
| `Region` | A provider's region code and its label, and which gateways are in it. Belongs to one `Geography`, fixed once a Network or Machine names it. |
| `Geography` | A residency boundary (`in`, `eu`), its public `endpoint`, and its own hosted zone (`fleet_zone`) with that zone's wildcard certificate (Issue Fleet Certificate; renewed daily per geography, pushed only to its boxes). Every box in it is named `<box>.<fleet_zone>`, and the endpoint is one label under that zone or the zone itself (the certificate covers both), checked for hostname shape only and blank until the operator fills it. Its gateways share one DNS set at that endpoint, are pushed only routes from inside it (replicas, ingresses and vendors with this `geography`, and every pod when it is the Pod Geography), and 403 a key pinned elsewhere. One Geography is **Is Default** (ticking it on one unticks the rest): a Grove API Key saved without a geography is pinned there. **Store Backups** tab: its own bucket + Put/Get key for Gateway Store RDBs (blank = no backups here). Every box carries a read-only `geography` copied from its Region (Machine sets it in validate; the rest `fetch_from`). Still leaves the geography: token counts to this site, and every key hash and team name to every gateway. |
| `Cloud Provider` | One account and its credentials. |
| `SSH Key` | The keypair a box is provisioned with. |
| `Monitoring Agent` | The scraper. A box's exporters only listen; this is what polls them. |

## Serving — what actually answers a request

| Doctype | Owns |
|---|---|
| `Model` | A model as one provider record serves it. The doc name is a hash; **Model Key** (`<provider name>/<model id>`) is what a caller sends, the route key and the usage bucket — set off the Model ID typed at creation and frozen. **Provider** links one record; a vendor with a record per Geography has a Model doc per record, all under one key, each with its own Upstream Model ID and Model Pricing (unique on provider + model id). **Geography** is fetched from the record, so two docs of one key tell apart in a list and a link picker. The provider's name is read off the record, never stored on the Model; the save refuses a link whose name is not the key's prefix, so it can move only between records of the same name. A Link anywhere means the doc; the key means the id — every Link holder (pricing, deployment, replica, pod, grant row, discrepancy) carries the key as a fetched column. One under the Self Hosted provider names an HF repo — that is what an engine serves, under the key, and what the S3 mirror is filled from; one a vendor serves names none, because there is no engine to start. `published` is the serving gate, ticked by hand: the gateways hold a route only while it is set. The save refuses a model with no Enabled Model Pricing, or with nothing serving it — a live deployment, a running pod, or a front on its own provider record. Nothing publishes on its own; a model nothing serves any more is unpublished on its own. Not an access gate. **Load Pricing** inserts the rates `catalog/catalog.json` holds for the key as a Disabled Model Pricing, while none names the doc. |
| `Denied Tool` | One tool a vendor would run on its own side and bill outside the token counts, which the gateway refuses to send it: a `tools[].type` (`web_search_20250305`) or a top-level request field (`web_search_options`), under the vendor's **Provider Name**. The name is the pair. Rides every provider route row of the vendor as `denied_tools`; a request that names one is a 400 at the gateway before the dial. Keyed by the name and not a Model Provider link: the list is the vendor's, and a vendor has a record per Geography. Delete the row once the tool is priced, and drop it from `catalog/catalog.json` too, or the next migrate seeds it back. |
| `Model Provider Key` | One credential of a vendor (child of Model Provider). The row name is the id the gateway picks, rotates and counts under; the secret itself is never named anywhere. **Title** is mandatory and one per provider: it is how Provider Key Stats names the key. **Disabled** keeps the row and its stats but pushes it to no gateway, so nothing dials it: disable first, delete once nothing missed it. |
| `Provider Key Stats` | What one key answered on one gateway store since the pull before, in `stats` (indented JSON, shown as code), by the 6-hourly pull and never updated; a key is its Model Provider and Title, a store its link. The gateway clears its counters as it answers; a store that did not dial the key leaves no row. |
| `Model Provider` | Who serves a model. The one flagged **Self Hosted** is ours: blank-provider Models are named under it, and only its models can be deployed. Every other provider is a vendor, dialled through its URL fields: with a **Base URL** (and at least one row in **Keys**), its published models route straight to the vendor and nothing is ever deployed for them. **Provider Name** is the namespace every model under it is named in, set once; the doc name is a hash. A vendor has one record per `Geography` it processes in, all under the same Provider Name (unique together), and each gateway dials its own geography's record — so `openai/gpt-5` is one key everywhere and a regional front (eu.api.openai.com) is a second record, not a second provider. A model routes in a geography when it has a doc under that geography's record: the catalogue is per record, so a regional upstream id or price is that doc's own. "EU" differs by vendor (OpenAI and Mistral include EEA/CH; Vertex is EU member states only). **Fetch Models** lists the vendor's own `/v1/models` (OpenAI front first, else Anthropic's) and adds the ticked ids as unpublished Models under the record. |
| `Model Deployment` | The logical service: one Model on one hardware shape. Owns the image, the GPUs-per-replica, and the tuning every replica of it runs. Named `MD-{#####}`, counted — several deployments of one model are normal (a second **shape**, or a rollout running old and new side by side). The name carries neither the model nor the shape: `gpus_per_replica` is editable while a name is not, so `4xh100` would go stale the first time someone re-shaped it. Deliberately **not** region-scoped: `deploy:<model>` is global, so replicas in different regions already stand in for each other, and one deployment rolls a model out everywhere. `placement_policy` names which scorers `find_placement` ranks boxes by (`grove/placement/`) — it only ORDERS boxes that could already take the replica, never admits one that could not. |
| `Model Replica` | One **replica** of a Model Deployment: which box, which cards, which port. Named `<model id>-<region>-<server>-<n>` (`qwen3-8b-ap-south-1-inf3-00007`). Re-derives its arguments at deploy time from the Engine its deployment builds — a `custom` image runs its own entrypoint and is gated at the box's proxy instead of by a key it does not enforce. Carries tuning where it **overrides** its deployment: blank or 0 there means inherit. `kv_cache_dtype`, `gpu_memory_utilization`, `max_num_seqs` and `attention_backend` are **prefilled**, so a new replica starts as an explicit override and editing the deployment will not move it — clear the field to hand ownership back. Migrated replicas were blanked, so they inherit. `kv_cache_memory` is the one tuning value Grove writes itself — learned off a profiled boot, applied while its key matches, dropped when a boot fails under it. Takes as many cards as its deployment declares — replicas of one deployment are interchangeable, which is what makes `replicas x capacity` arithmetic. |
| `Model Replica GPU` | Which GPUs that replica was **given** (child) — the run script's `--tensor-parallel-size` and CUDA pinning. Not the claim. |
| `Pod` | A standalone RunPod vLLM instance. Fully self-contained — its own spawn/sync/restart/terminate, and it registers its own endpoint with the gateways of Grove Settings' `pod_geography` — every pod serves in that one geography (blank routes none). Sends its **stored** `serve_command`, so it must be saved before it is re-spawned. `provision_at` / `terminate_at` (Up From / Down From) are a daily window the every-minute tick (`cloud_provider/schedule.py`) keeps it inside — spawned once per day while inside and unprovisioned, terminated while outside and live; a spawn re-asks the provider `provision_retries` times (the create call only); every lifecycle call leaves a `Pod Activity` row. |
| `Pod Env` / `Pod Port` | That pod's environment and its port pool (children). |
| `Engine Image` | The container image an engine is spawned from, and what only the image knows: its `engine_kind`, and for a `custom` one the warmup request (path + body) that proves it serves. Both placements read them, so the same image warms up the same way wherever it runs. |
| `Engine Image Provider` | A registry and the credentials to pull from it. One record per registry. |

## Tenancy — who may call what

| Doctype | Owns |
|---|---|
| `Grove Team` | A control client's team — Central's (`TEAM-00520` is the doc name) or Press's (`Press Team`) — named by the client's id for it. Every `grove.api` call names the team by it, and `api.teams.provision_team` upserts by it. Grove keeps nothing else about who the team is — no email, no login; contacts are the client's. What is the team's is its `tier` and the house rules, set by Central (`api.teams.update_team`; an edit in Desk is overwritten on the next sync; the tier is picked in Desk only when the team is made, read-only after). A tier change arrives by Central's Frappe Webhook at `api.teams.team_webhook`, a guest endpoint that checks the body's HMAC against the control user's `api_secret` (`X-Grove-Control-Key` names the user by its `api_key`); the body carries `observed_at`, when Central read it, kept as `last_reported_at`, and one not newer is a retried or reordered delivery, ignored. A team Grove does not know is ignored too, since AI is off for it. The Tier names `max_keys`, how many live keys it may hold (0 is no limit), which is what bounds its throughput since rate limits are per key; `spend_limit` (USD a month), which what its keys spent this month and the live caps together stay within (`pricing.committed`); and the rate limits its keys run under when they carry no limit rows of their own (blank tier: the default tier in Grove Settings). **Override Max Keys** pins the team's own `max_keys` instead; `access.team_limits` resolves which apply. `suspended`, set when an invoice goes unpaid and pushed as `limited` on every key of the team; the form's **Suspend Keys** button (`set_suspended_at_grove`) sets it too, with `suspended_at_grove` beside it to say the hold is Grove's, which Central's sync cannot lift (`validate` keeps `suspended` on while it is ticked). Resume Keys clears both; Central puts its own back on its next sync. `key_cap_window`, what each of its keys' caps counts — **Monthly**, this UTC month's spend, or **Total**, everything since the key was minted, so a spent key stays spent (a trial team) — operator-set when the team is made and fixed after (the gateway keeps a different counter per window, so a change would restart every key's count), pushed on every key of the team as `budget_window`. A Total team has no spend limit: its caps are for life, so what the month has spoken for binds nothing (`needs_cap_check`, `api.keys.update_caps` skip the check, `figures` reports `spend_limit` null), and `max_keys` with the revokes bound it instead. `log_payloads`, whether the gateways store the prompts and outputs of the team's keys, on by default; the team sets it from Central's console (`api.teams.update_team`), and `api.usage.figures` reports it. Policy lives on the keys. The gateway holds no team record. A site from before this doctype is moved by the `move_grove_users_to_central_teams` patch: one team per Grove User (named by its reference, else its old name), each key given the user's geography, groups, grants and limits, and its spend from the records; every key starts at a cap of 0. Renamed from `Central Team` by `rename_central_team` (2026-10-22): a team at Grove is any control client's. |
| `Tier` | What a team on it may do, named by Central's trust tier label (`Beginner`, `Growth`, `Intermediate`, `Advance`, `Power`, `Elite`): `max_keys` (0 is no limit), `spend_limit` (USD a month across the team's keys, their caps and what they spent; 0 lets no cap be set) and `limits` rows of `Model Limit`, the rate limits its keys run under when they carry none of their own (one per metric and window; no rows is explicit, uncapped). Central names a team's tier (`Grove Team.tier`, through `api.teams.update_team`); the values are Grove's, tuned in Desk — the catalog seeds the six once with starter values and never updates them. `Grove Settings.default_tier` is what a team with no tier runs under and what a tier Central names before Grove has one is cloned from (`ensure`; no default: the hard-coded rate limits, no key limit, spend limit 0). An edit reaches every team on the tier at once, and its unpinned keys at the next push. When Central renames a label, `api.teams.rename_tier` renames the Tier and every link follows; a label Grove never saw is nothing to rename, and a name Grove already has is refused, not merged. A tier a team names cannot be deleted. System Manager edits; Grove Control reads, creates and renames. |
| `Model Group` | A named set of models in one **Geography** (required, set once; left blank it is the default one). A vendor model in it is that geography's doc, so the row is the doc and price its members reach; a model of ours goes in any group, since it serves wherever a replica runs. Membership lives on `Grove API Key`, which lists the groups it is in — there is no member table; its form offers only groups of the key's own geography. A key reaches the union of all of them. The one ticked **Is Default** (one per geography) is put on every new key of that geography that names no group of its own, so whoever mints a key sends no model list; with none ticked there a new key reaches nothing until a group is added to it. The gateways still get every group as a key list. `api.catalog.available_models(team, key)` lists what a key reaches (`access.get_reachable_models`: groups and Allow, less Deny), for a control client to show. |
| `Grove Model Row` | One model in a grant (child): the doc, and its `model_key` fetched beside it — the id a caller sends, what the gateway matches and what the projection reads without a join. Off the grid, since the doc's title already names it. |
| `Model Group Row` | One group a key belongs to (child). |
| `Model Limit` | One rate limit on its parent (child of a Grove API Key or a Tier): `metric` (`requests`, `total_tokens`), `window` (`1m`, `1h`, `1d`, `1M`, reset on the UTC clock) and `value`. One row per metric and window (`access.validate_limit_rows`, the same rule on both parents). The gateway refuses a push carrying a metric or window it does not know, so a new option ships in pathway first. |
| `Grove API Key` | One credential and the whole policy behind it, unique by `key_hash` (the index is what makes the 192 random bits' uniqueness a guarantee, and what every lookup by hash uses). It belongs to one `team` (Grove Team) and works in one `geography`, both set once: left blank it is the default Geography, and gateways elsewhere answer 403 — its spend and rate counters live on that geography's store, which is what lets that store gate it exactly; a team spans geographies by minting a key in each. What it may call: the groups it is in (`model_groups`, its geography's — one of another's is refused; a new key starts in the one marked default there, or in the one `provision_key(model_group=)` names) plus its own `allow`, less its `deny` (a vendor model in either is its geography's doc). `cap` is what it may spend over its team's `key_cap_window`: pushed as `budget` with `budget_window`, and the gateway, which counts the key's spend per UTC month or in one total since the mint, refuses it at 402 once that reaches the cap; 0 until a cap is set and refused until then, and across the team's keys what the month has spoken for — each live key's cap or its month's spend, whichever is more, plus what revoked keys spent (`pricing.committed`) — never exceeds the team's `spend_limit` (checked on a raise and a mint with a key's month as the records or what its box counts, whichever is more, `usage.peek_team`; the team row is taken ahead of the key's own and the boxes read under it, so two raises queue rather than deadlock and a mint past its key count never dials; so a lowered limit stops no key, a key can always be minted at 0, and a revoke frees its cap but never its spend). What it spent this month is read off the records and corrections (`pricing.month_spent_by`), never stored. `limits` are its own rate limits (`Model Limit` rows): with none, it runs under its team's Tier, else the default tier, else the defaults (`access.DEFAULT_LIMITS`, 20 requests and 100 000 tokens a minute). Whichever applies is pushed as one sorted `metric:window:value` list and counted on the gateway under the key's prefix, per Gateway Store: requests as they are admitted, tokens once the answer reports them, and a key over one gets 429 with `Retry-After`; a tier with no rows is uncapped. `title` is a label to tell a team's keys apart, set once at the mint, and a unique index on (team, title) makes it used once per team, ever, revoked keys included (Press titles a trial site's key by the site, and a site must never get a second); blank is no title, stored as NULL, which the index never counts as a twin. `expiry` is the rule it retires by, set at the mint (`provision_key(expiry=)`: Never, or 1, 7, 14 or 30 days) and fixed after, and `expires_at` the moment that names; `revoke_expired`, hourly, revokes every live key past it and the next tick prunes it off the boxes, so an expired key answers for an hour at most. With `expiry_from_first_use` (set at the mint too, `provision_key(expiry_from_first_use=)`) the rule counts from the key's first usage record instead: `expires_at` stays empty until `grove_api_key.start_expiry`, called as `pathway/reconcile.py` lands the records, sets it once, so a key minted ahead and held in stock — Central's trial pool — does not age on the shelf. `api.keys.extend_key(team, key, days)` moves `expires_at` by `days` from now or from its moment, whichever is later — what Central sends when an operator extends a trial; a key without a moment is left as it is, a revoked one refused. `figures` lists all three. `api.keys.transfer_key(team, key, to_team, title)` hands a key to another team — what Central sends when a trial converts, so the secret the customer's server holds keeps working: the team and the title move and the trial's rules go (the geography's default group in place of its groups, its expiry lifted to Never), in one save, which the Version records and the next tick re-pushes; cap, geography and limit rows stay as minted; counted against the new team like a mint (its key count, and its cap within a Monthly team's spend limit); a key the receiving team already holds is answered as it is; one between two teams of the same cap window is refused (the box keeps a key's spend under one field per window, so it would follow the key). The box closes the old team's books at that push (a set-aside stamped `team`, landed under it by `pathway/usage.py`), so what the key spent before the move stays the old team's, and `month_spent_by("api_key")` sums only the records under the key's team now. The secret is handed out by `api.keys.provision_key`, and again only to the control client by `api.keys.secrets` (every live key of a team with its secret, for the team's own servers to hold); `api.usage.figures(team)` lists a team's keys masked to the prefix and four characters (never the end; `masked`, kept on the key at mint, so a listing decrypts nothing), each with its geography and endpoint, cap and `month_spent`, the limits the gateway counts, the `key_hash` that narrows `api.usage.usage`, and `revocable_at`, the UTC moment a new key may be revoked (`REVOKE_AFTER_HOURS`, six, guards a create-and-revoke race). `api.keys.update_key` changes cap, models and limits (`limits=[]` puts a key back under its tier); `api.keys.update_caps` sets several of a team's caps in one call, lowers first, refused whole when the total would pass the spend limit; `api.keys.revoke_key` takes `team` and the key's name, refused when another team holds it; a revoked key stays revoked, mint a new one. The gateway's `/v1/credits` answers a key its own cap less this month's spend, nothing of the team's. |
| `Grove Settings` | Single. The fleet-wide knobs: Pod Geography (where every pod serves), Default Tier (what a team with no tier runs under, and what an unseen tier name is cloned from), Usage Retention (how long a gateway keeps acked usage; rendered into its `config.json`), DNS provider (owns every geography's zone), ACME email, pathway release and repo, monitoring (the Service Discovery Token every agent presents: at least 16 URL-safe characters, checked as it is set), the weights bucket and its two key pairs (engine read; Mirror write). |

## Logs — what happened, and to which box

Append-only. Never read to decide anything; read to find out why.

| Doctype | Owns |
|---|---|
| `Pathway Sync` | One push run. Its list view holds **Force Sync All** — the fleet-wide force-push. |
| `Pathway Sync Row` | One TARGET in that run (child) — names the **doctype as well as the box**, because the two planes take different pushes. |
| `Gateway Deletion` | One Redis record a box still holds and should not. Every other push is an UPSERT, so without this a revoked key would keep working. |
| `Pod Activity` | One lifecycle call on a Pod — spawn attempt, restart, stop, start, terminate — with its trigger (button or tick), outcome, duration and the provider's error. Written by `PodProvisioner`, never read to decide anything. |
| `Pathway Update` | Deploys Grove Settings' Pathway Release (and Repo, both copied read-only at insert) to chosen servers, one `Pathway Update Server` row (child) at a time. The Gateways / Ingresses boxes are set once: they add every Active server of that type at insert and limit which types rows may name; rows can be added or deleted whenever it is not running. Never starts by itself. **Start** checks nothing else is running, the pin still matches, the Pending servers are Active and the release is published, then runs `_deploy_agent` per Pending row through `runner.StepHandler` — which records `agent_version` on the server. A failed deploy stops it (traceback on the doc, Error Log, notification) and puts the failed server (gateway or ingress) in maintenance to be debugged — End Maintenance on it when done; **Continue** carries on past failed rows, and re-adding a failed server as a row retries it. **Stop** takes effect between servers, never mid-deploy. Start/end times on the update and on each row. |
| `Ansible Play` | One playbook run. Its status is written by the callback and so is best-effort; what a caller acts on is Ansible's own rc, never this. |
| `Ansible Task` | One task in it, created as it starts — including handler tasks, or a failure inside a handler produces a play that failed with no row saying why. |

## Conventions these all follow

- **Box names are generated, never typed** (`grove/naming.py`): a Machine is `<prefix><n>-<region>`,
  the prefix from its Machine Type (`NAME_PREFIX`), counted per region out of `tabSeries`, and the
  server doc on it takes the Machine's name. The first label carries the region as a suffix rather than a
  namespace — `*.<zone>` covers `gw1-ap-south-1.<zone>` and nothing deeper — and a box whose Geography has a zone is
  named with it (`gw2-ap-south-1.<zone>`), so its domain shows at a glance. Request ids and agent ids carry only the
  first label (`short_name`); boxes named before this keep their short names.
- **A replica's name says what it serves and where** (`grove/naming.py`):
  `<model id>-<region>-<server>-<n>`, e.g. `qwen3-8b-ap-south-1-inf3-00007`. The region goes in as
  its provider codes it — no shortening rule, since `ap-south-1`, `asia-south1` and `southeastasia`
  share none. The box contributes only the part of its name that is not the region (`inf3`), and
  the number comes out of the same `MD-` series the old `MD-00007` names used — kept as `MD-`
  through the rename because it is a counter key, not a label. The name is also the engine's
  container name (`vllm-<name>`) and its path on the box's proxy, so it is never renamed after
  insert.
- **A deployment's name is `MD-{#####}`** (`grove/naming.py`), off the SAME `MD-` series, so one
  number is handed out once and an `MD-` name never means two things — replicas predating the
  descriptive format are still named `MD-00010`, and a route row's `deployment=` carries a replica
  name. It says neither the model nor the shape: `gpus_per_replica` is editable and a name is not.
- **A cloud resource id lives in a read-only `Data` field**, written with `db_set`, and its creator is
  guarded by `if self.<id>: return` (see `Network.create_network`). That is what makes provisioning
  re-runnable.
- **A doctype standing on a box extends `Server`** (`grove/server.py`): its name is its
  Machine's (a name passed on insert wins), it calls `run_playbook("x.yml")` — never
  a path, a server type or a Machine — and it is retired with `Archive`. Archive refuses while
  anything depends on the box: each doctype lists its own dependents in `archive_blockers`
  (replicas on an Inference Server, boxes routed through an Ingress, targets of a Monitoring Agent,
  the last gateway of a region that still serves, gateways still on a Gateway Store), then a cloud Machine is terminated, whose
  cascade already marks the row Terminated and drops its DNS. An on-prem box only has its row retired.
  A cloud Machine launches with Termination Protection on; while the provider reports it on, Terminate
  (and so Archive) refuses before anything is released. Its button turns it off.
  A bare-metal Machine that is gone is retired with its own `Terminate`: no provider call, just the
  same cascade. An Inference Server going Terminated takes its replicas with it — the box is
  gone, so no teardown play runs and only their rows (status, port) are retired.
- **A new Inference Server takes the Network's only ingress and only monitoring agent** when there
  is exactly one of each (`default_to_network_singletons`); two or more stay an operator's pick.
- **An Inference Server is fronted by an ingress or is Standalone.** Standalone skips the ingress:
  gateways dial `<short name>.<its geography's zone>` (DNS record follows the flag), its nginx serves the fleet
  wildcard, and renewals reach it through `tls.push_to_proxies`. Neither saves with a banner; Setup refuses.
- **A connections badge counts live rows.** `grove/notifications.py` names the "open" filter per
  doctype — a Network's Machine link and a Model Deployment's Model Replica link show the Active
  ones, a Pod's Activity link the failed ones — and the total stays in the count.
- **Long buttons enqueue.** `frappe.enqueue_doc(..., queue="long")`, and the worker method carries
  `@failure.reports_failure` so a crash marks the doc Broken with the reason on it.
- **A button that changes a box or a record confirms first.** `grove.confirm_call(frm, message,
  method)` (`public/js/confirm_call.js`); the message says what happens. Reads (Ping, Check State,
  GPU Memory, AWS Sync) stay one click.
- **A child table row names the thing it is about.** Frappe silently drops an `append()` key that is
  not a field, which is how a row full of numbers with no server on it got shipped once.
